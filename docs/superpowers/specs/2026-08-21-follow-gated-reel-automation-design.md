# Follow-Gated Reel Automation Design

Date: 2026-08-21

## Objective

Add a production-safe Instagram automation that lets a workspace owner choose one or more Instagram posts or Reels, match comment keywords, send a public comment reply and an opening private message, verify whether the commenter follows the connected professional account, and release a configured link only after Meta confirms the follow relationship.

The feature must use Meta's official Instagram API with Instagram Login and deterministic user-authored messages. It does not use AI, scraping, browser automation, or unofficial Instagram endpoints.

## User Experience

The automation builder becomes a guided campaign setup with these stages:

1. **Choose content**
   - Specific posts or Reels selected from a visual media grid.
   - Any current or future post/Reel.
   - The next post/Reel published after activation.
2. **Choose the comment trigger**
   - Any comment.
   - Comment contains one or more case-insensitive keywords.
3. **Configure public replies**
   - Zero to five reply variations.
   - ReplyConnect rotates variations deterministically to reduce repetitive replies.
4. **Configure the opening DM**
   - One message with an opt-in quick reply or postback button.
   - The opening DM does not contain the protected link.
5. **Configure the follow gate**
   - Message shown when Meta says the person is not following.
   - `I've followed` button that asks ReplyConnect to check again.
6. **Configure delivery**
   - Final text and URL or button.
   - Sent only when Meta returns `is_user_follow_business: true`.
7. **Review and activate**
   - Summary of selected media, keywords, reply variants, and messages.
   - Test mode and activation controls.

The activity screen shows the originating post/Reel, matched keyword, public-reply result, DM opt-in status, latest follow-check result, final delivery result, and timestamps.

## Meta Platform Constraints

- The commenter must interact with the opening private message before ReplyConnect can read the Instagram User Profile API fields. A comment alone does not grant profile consent.
- Follow status is read from `is_user_follow_business` using the Instagram-scoped sender ID from a messaging webhook.
- The initial private reply to a comment can be sent only once for a user on a post/Reel and must follow Meta's private-reply timing rules.
- Continued automated messaging must remain within Meta's active messaging window.
- There is no public follow-change webhook in the current integration. ReplyConnect rechecks when the person taps `I've followed`; it does not continuously poll Meta.
- The automation handles content owned by the connected account and content Meta exposes through that account's media edge. Unsupported remixes or ad-only creatives are not shown in the picker.

## Architecture

### Media Catalog

Add a workspace-authenticated endpoint that loads media from the connected Instagram account through Meta:

`GET /api/meta/media`

The Meta client requests media fields needed by the picker: ID, caption, media type, media product type, permalink, media or thumbnail URL, and timestamp. The endpoint returns a normalized, paginated media list and never exposes the Instagram access token.

The UI loads media on demand. Temporary Meta CDN URLs are used only for display and are not treated as permanent assets. The saved automation stores media IDs and immutable metadata snapshots needed for audit display, not access tokens or downloaded media.

### Flow Definition Version 2

Introduce a versioned definition while continuing to read existing version 1 automations.

The version 2 definition contains:

- `trigger.source`: `specific_media`, `all_media`, or `next_media`
- `trigger.mediaIds`: selected IDs for `specific_media`
- `trigger.match`: `keyword` or `any`
- `trigger.keywords`: normalized keyword list
- `publicReplies`: zero to five text variants
- `openingMessage`: text plus opt-in button label and opaque postback payload
- `followGate.required`: boolean
- `followGate.notFollowingMessage`: text
- `followGate.recheckButtonLabel`: text
- `delivery`: final text, URL, and optional button label

Validation rejects empty required messages, malformed URLs, missing media selections, duplicate keywords, oversized text, and postback payloads not generated by ReplyConnect.

### Public Comment Replies

Add a Meta client method that replies to the triggering comment through the official comment-replies endpoint. A stable hash of automation ID and comment ID selects one configured reply variation, ensuring retries use the same variation.

Public-reply failure is recorded independently. A retryable public-reply error can be retried without duplicating the private reply or final delivery.

### Opening Private Reply and Consent

For a matching comment, ReplyConnect:

1. Records a campaign participant keyed by workspace, automation, Instagram account, media, and commenter/comment identifiers.
2. Sends the optional public reply.
3. Sends one opening private reply containing a postback or quick-reply action.
4. Waits for a messaging webhook from the person.

The opening interaction payload contains a signed opaque reference to the automation and participant. It does not contain the final URL or database identifiers that can be modified safely by a user.

### Participant State

Add an `AutomationParticipant` persistence model with:

- workspace and automation IDs
- connected Instagram account ID
- Instagram-scoped participant ID when consent is established
- source comment ID and media ID
- source media snapshot
- matched keyword
- lifecycle state
- opening/public/follow-check/final-delivery timestamps
- last known follow status and checked-at timestamp
- messaging-window expiry
- idempotency keys and provider message IDs

Lifecycle states:

- `COMMENT_MATCHED`
- `OPENING_SENT`
- `OPTED_IN`
- `FOLLOW_REQUIRED`
- `FOLLOW_VERIFIED`
- `LINK_SENT`
- `EXPIRED`
- `FAILED`

Transitions are monotonic except that a retry may remain in the same state. Unique constraints prevent duplicate participants and duplicate final delivery.

### Follow Verification

After the opening postback/message provides an Instagram-scoped sender ID, the Meta client requests:

`fields=is_user_follow_business`

Behavior:

- If true, mark `FOLLOW_VERIFIED` and send the final delivery once.
- If false, mark `FOLLOW_REQUIRED` and send the follow prompt with an `I've followed` postback.
- On that postback, query Meta again.
- If still false, send a concise not-yet-following response with the same recheck action, subject to anti-loop limits.
- If the profile endpoint returns a consent or permission error, do not send the link; record a visible diagnostic.

Rechecks are user-initiated. Limit checks per participant and apply a short cooldown to protect API quota and avoid button spam.

### Webhooks

Expand app subscriptions from `comments,messages` to include the supported interaction fields required by the flow:

- `comments`
- `messages`
- `messaging_postbacks`
- `messaging_optins`
- `messaging_referral`

Normalize postback and opt-in payloads while preserving sender ID, recipient account ID, timestamp, and signed payload. Signature verification remains mandatory before parsing.

The worker routes events by participant state before evaluating standalone message automations. This prevents a follow-gate postback from accidentally triggering a generic DM keyword automation.

### Next-Media Mode

When an automation is activated with `next_media`, the system persists an `activatedAt` timestamp. For the first candidate comment webhook, it resolves the media's publish timestamp and only accepts media published after `activatedAt`; the automation is then bound to that media ID atomically. This prevents delayed webhooks or comments on older posts from capturing the automation. Once bound, comments on other media do not match it. The UI shows the bound media after the first event.

This avoids requiring content-publishing permission or periodic media polling solely to discover the next post.

## Error Handling and Idempotency

- Every external delivery has a deterministic idempotency key.
- Retryable Meta errors are retried by the existing worker queue.
- Permission, consent, expired-window, deleted-media, and invalid-recipient failures become terminal participant diagnostics.
- A link is never sent when follow state is false, unknown, stale because of an API failure, or unavailable.
- Disconnecting an Instagram account expires pending participants and removes their usable token.
- Meta data deletion removes participants and their derived activity data with the existing workspace deletion transaction.
- Deauthorization removes the connection and expires pending participants.

## Security and Privacy

- Access tokens remain encrypted at rest and are never returned to the browser.
- Postback payloads are signed and time-bounded.
- Workspace authorization is enforced on media, automation, participant, and activity endpoints.
- URLs are validated as HTTPS by default, with localhost exceptions only in development.
- Participant data is retained only as needed for automation delivery and review/audit history, then removed according to the product retention policy.
- Privacy and data-deletion disclosures are updated to mention participant profile fields and follow-status checks.

## Testing

### Unit tests

- Version 2 definition validation and version 1 compatibility.
- Keyword/media matching and next-media atomic binding.
- Deterministic public-reply rotation.
- Signed postback creation and verification.
- Follow-status true, false, unavailable, and API-error branches.
- State-transition and duplicate-delivery protection.
- Messaging-window and recheck cooldown enforcement.

### Integration tests

- Media endpoint normalization without token exposure.
- Comment webhook through opening private reply.
- Postback through user-profile check and final delivery.
- Non-follower prompt followed by successful recheck.
- Webhook retries do not duplicate public replies, private replies, or links.
- Data deletion and deauthorization clean up participant state.

### UI tests

- Media picker loading, empty, pagination, and error states.
- Specific/all/next source controls.
- Keyword and reply validation.
- Follow-gate preview and final review summary.
- Accessible keyboard and screen-reader behavior.

### Live Meta test

Use the connected tester account and a separate tester sender account:

1. Select a test Reel and activate the automation.
2. Comment the configured keyword.
3. Confirm public reply and opening DM.
4. Tap the opening action.
5. Confirm the non-follower prompt.
6. Follow the professional account.
7. Tap `I've followed`.
8. Confirm the link is delivered once and activity attributes it to the correct Reel.

## Rollout

1. Ship schema and read compatibility before enabling the new builder.
2. Deploy Meta client and webhook support behind a server-side feature flag.
3. Subscribe the connected tester account to the additional webhook fields.
4. Run the full tester-account flow.
5. Enable the version 2 builder for the owner workspace.
6. Update Meta App Review instructions and screencast to demonstrate follower verification.
7. Keep existing version 1 automations operational until explicitly migrated.

## Acceptance Criteria

- The owner can visually select one or more available posts/Reels without copying media IDs.
- A configured keyword comment on selected media produces the configured public reply and opening DM once.
- The final link is not sent before the user opts in and Meta confirms `is_user_follow_business: true`.
- A non-follower receives a follow prompt and can trigger a real status recheck.
- The final link is sent once after successful verification and is attributed to the correct media source.
- Existing automations continue to run.
- Tests, lint, production build, migration deployment, and a live Meta tester flow pass before release is called complete.
