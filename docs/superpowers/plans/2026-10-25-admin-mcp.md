# Linkar Admin MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An MCP server that lets a platform owner run everything the owner console can do (users, workspaces, plans, invite codes, integrations, operations, deletions, system, audit) from Claude.

**Architecture:** A stateless Streamable HTTP MCP endpoint at `https://admin.linkar.in/api/admin/mcp`, inside the existing Next.js app. Callers authenticate with owner-minted MCP keys (Bearer tokens). Each tool calls the existing `/api/admin/*` route handler in-process, inside an AsyncLocalStorage "key principal", so the same validation, audit, owner-workspace protection, version locks and confirmation challenges apply. The HTTP API itself never accepts keys.

**Tech Stack:** Next.js 16 route handlers, Prisma 6 (PostgreSQL), zod 4 (`z.toJSONSchema` for tool input schemas), Vitest. No new dependencies. The MCP JSON-RPC layer is hand-written.

**Spec:** User request "create a full fledged admin mcp for linkar controlling everything"; the user skipped design questions, so this plan records the design decisions (below).

## Design decisions (made by Claude, user skipped questions)

- **Where it runs:** inside the web app on the admin host. No separate deployment, no production secrets on a laptop.
- **Auth:** MCP keys created on the owner console **Security** page, only from an AAL2 (TOTP) session. A key can never mint or revoke keys, or touch MFA.
- **Key format:** `lkadm_` + 43 base64url characters (32 random bytes). Only the SHA-256 hex digest is stored; the full key is shown once.
- **Scopes:** `READ` (read tools only) and `WRITE` (all tools). Exports, deletion previews and challenge-issuing steps count as writes because the console audits them.
- **Expiry:** 1, 7, 30 (default) or 90 days. At most 10 active keys per owner (`mcp_key_limit`, 409).
- **Key validity on every request:** not revoked, not expired, owner still in `PLATFORM_OWNER_USER_IDS`, owner's platform control `ACTIVE`, and key created at or after the owner's `sessionInvalidBefore`. Any failure answers 401 `invalid_mcp_key`.
- **Audit identity:** actor = owner UUID and the email stored on the key; `sessionId` = `mcp_key:<keyId>`; `origin` = `mcp`; the user agent and client address are those of the MCP client.
- **Failed auth rate limit:** 10 failures per 15 minutes per client network (`LoginRateLimitStore`, namespace `admin-mcp`), then 429.
- **Protocol:** JSON-RPC 2.0 over POST, JSON responses only (no SSE, GET/DELETE answer 405), no batching, no sessions. Supported protocol versions `2025-11-25`, `2025-06-18` and `2025-03-26`.
- **Write tools** take a required `reason` (3–500 chars) and an optional `idempotencyKey` (`^[A-Za-z0-9._:-]{16,128}$`; generated when absent).

## Global Constraints

- No new npm dependencies.
- Every `/api/admin/*` route handler except `security`, `mcp` and `mcp-keys` must be reachable by at least one tool (enforced by a test).
- Secrets never appear in audit rows, logs, tool listings or error messages. The plaintext key is returned exactly once, by the mint route.
- Keys are refused everywhere except the MCP endpoint: the regular admin HTTP API keeps cookie + AAL2 auth only.
- Copy follows the console's existing tone. UI is built only from existing admin shared components.

## Review Focus

- A READ key calling a write tool: refused with `mcp_key_read_only` both by the tool listing (not listed) and by the guard (403) if called by name.
- A revoked or expired key, or a key whose owner was removed from `PLATFORM_OWNER_USER_IDS`: 401 on the very next request, never a cached success.
- A cross-origin browser POST to the MCP endpoint (DNS rebinding): 403 before auth.
- A tool whose route answers CSV (audit export, workspace export, contact export): CSV text in the result, not a JSON parse failure.
- A JSON-RPC notification (`notifications/initialized`): 202 with no body, never a JSON-RPC error.
